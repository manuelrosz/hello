Guía Profesional de Git para Unirte a un Proyecto Nuevo

Autor: Manuel · Uso: repos nuevos, repos existentes, repos con historia previa, repos vacíos.

1. Crear un repositorio local nuevo

Cuando empiezas en una carpeta vacía o con código nuevo:

git init

Esto crea el repositorio Git dentro de la carpeta actual.

2. Conectar el repositorio local con un remoto

Usa la URL SSH del repositorio remoto:

git remote add origin git@github.com:usuario/repositorio.git

Verifica que quedó bien:

git remote -v

3. Caso A — El repositorio remoto está vacío

GitHub recién creado sin archivos
  1. Agregar archivos: 
    git add .
  2. Crear commit inicial: 
    git commit -m "Initial commit"
  3. Subir al remoto: 
    git push -u origin master

4. Caso B — El repositorio remoto ya tiene archivos

historia previa commits antiguos

Antes de subir tus archivos locales, debes traer la historia remota:

git pull origin master --allow-unrelated-histories

Si hay conflictos, Git te lo indicará.

5. Resolver conflictos

Cuando Git marca conflictos, verás algo así dentro del archivo:

<<<<<<< HEAD
(tu versión local)
=======
(versión remota)
>>>>>>> commit

Pasos:

  1. Abrir el archivo con conflicto (VS Code recomendado).
  2. Elegir una opción:
    • Conservar tu versión.
    • Conservar la versión remota.
    • Fusionar ambas manualmente.
  3. Eliminar las marcas <<<<<<<, =======, >>>>>>>.
  4. Guardar el archivo.
  5. Marcar como resuelto: 
    git add archivo
  6. Continuar el rebase: 
    git rebase --continue

6. Subir tus cambios después del merge/rebase

git push -u origin master

7. Flujo diario de trabajo

Ver qué cambió

git status

Ver diferencias

git diff

Agregar cambios

git add .

Crear commit

git commit -m "mensaje claro"

Subir cambios

git push

Traer cambios del remoto

git pull

8. Ver el historial de forma profesional

git log --oneline --graph --decorate

9. Trabajar con ramas

Crear una rama nueva

git checkout -b nombre_rama

Cambiar de rama

git checkout nombre_rama

Fusionar ramas

git merge nombre_rama

10. Resumen ultra corto

git init
git remote add origin <url>
git pull origin master --allow-unrelated-histories
git add .
git commit -m "mensaje"
git push -u origin master

11. Notas profesionales

  • Trabaja siempre dentro de la carpeta que contiene el código, no en la carpeta padre.
  • Usa VS Code para resolver conflictos: visual, claro y seguro.
  • GitHub Desktop es ideal para ver historial, ramas y cambios.
  • La terminal sigue siendo la herramienta más precisa para merges, rebases y conflictos.
